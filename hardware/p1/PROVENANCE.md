## Repeat from hardware/p1

```sh
KICAD_CLI=/path/to/kicad-cli
python3 generate_schematic.py
"$KICAD_CLI" sch export netlist --format kicadxml -o p1.xml p1.kicad_sch
python3 portable_netlist.py
"$KICAD_CLI" sch erc --exit-code-violations -o erc.rpt p1.kicad_sch
python3 generate_board.py
"$KICAD_CLI" pcb drc --refill-zones --save-board --schematic-parity --severity-all --exit-code-violations -o drc.rpt p1.kicad_pcb
"$KICAD_CLI" pcb drc --schematic-parity --severity-all --exit-code-violations -o drc.rpt p1.kicad_pcb
"$KICAD_CLI" sch export svg -o preview p1.kicad_sch
"$KICAD_CLI" pcb export svg --mode-single --page-size-mode 2 --exclude-drawing-sheet --layers F.SilkS,F.Cu,Edge.Cuts -o preview/front.svg p1.kicad_pcb
"$KICAD_CLI" pcb export svg --mode-single --page-size-mode 2 --exclude-drawing-sheet --layers B.Cu,Edge.Cuts -o preview/back.svg p1.kicad_pcb
"$KICAD_CLI" pcb export step --force --user-origin 100x80mm -o mechanical/p1.step p1.kicad_pcb
python3 audit.py
```

The sourcing revision changed only hidden PCB MPN fields (U1/R3), not routing, saved fill, lands, placement or model references. Board SVGs and assembled STEP are therefore retained; ERC, saved-board parity DRC, schematic SVG and XML were re-exported. XML design/source is normalized after export; upstream model attribution is unmodified. The later candidate freeze adopted a fresh KiCad 10.0.8 front ground fill. The board previews were re-exported; package geometry and the assembled STEP did not change. Independent Gerber geometry checks matched all four copper layers across the saved board and two disposable refills.

`SHA256SUMS` identifies this particular set of local design files and exports, not a signed release. `bench-record.csv` contains unrun dummy-load cases only.
